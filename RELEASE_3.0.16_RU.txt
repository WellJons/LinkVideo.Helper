LinkVideo.Helper 3.0.16 — тестовая версия

Две отдельные учётные записи:
- «MikroTik» — вход для управления маршрутизаторами, как прежде.
- «Админка» — отдельный логин и пароль для B2O и CRM (клиентов, камер и тарифов).
- В боковой панели показываются два одинаково оформленных аккаунта. В админку можно войти, сменить данные, проверить доступ или удалить сохранённые данные. В названиях нет дополнительных входов B2O/CRM.
- Форма админки оформлена как форма входа MikroTik, с переключателем видимости пароля и галочкой «Запомнить».
- После успешной проверки данные админки сохраняются отдельно через Windows DPAPI и могут автоматически проверяться при следующем запуске.
- Пароль MikroTik никогда не используется для входа в админку. Токены B2O и CRM технически независимы, но используют одну учётку админки.
- При смене админки сбрасываются старые сессии; при отказе входа пароли не записываются как подтверждённые.

Исправление «Новый Агент»:
- При поиске следующей камеры сохраняется выбранный тип настройки и автоматически загружается значение новой камеры.
- Поле битрейта обновляется даже при совпадении значений на двух камерах.
- Ручная кнопка обновления читает именно текущую камеру. Устаревшие значения нельзя применять до успешного чтения.

«Поиск и управление»:
- Рабочие сценарии разделены на «VPN · поиск и управление» и «Камеры · проверка и превью».
- Проверка камеры по ID B2O доступна независимо от наличия VPN-аккаунта.
- Показываются DVR-сервер, IP (если его возвращает B2O), результат ICMP и TCP-проверки RTSP-порта с рабочего ПК, а также превью через существующий B2O API.
- Диагностика RTSP непосредственно с тестового сервера пока не реализована; открытый TCP-порт не означает работоспособность видеопотока.

Архив и серверы:
- Сохранён существующий реестр DVR B2O, поиск плейлистов, таймлайна и reserve-transfer.
- При обращении к карточке камеры ранее неизвестный действующий DVR автоматически добавляется в историю поиска. Новые источники из плейлиста также запоминаются.
- Если HLS-плейлист пуст, выполняется ограниченная проверка DVR-таймлайна на подтверждённом B2O сервере; найденные интервалы используются для скачивания.
- Изменение относится к архивным vcore, а не к перечню VPN-серверов.

Запуск:
- Отключено фоновое создание семи неоткрытых пользователем страниц при запуске программы.
- Применяемая ранее защита скрытия консольных дочерних процессов сохранена.
- Полное исчезновение кратковременных окон на рабочих ПК требует ручной проверки.

Возможности 3.0.15 сохранены. Экспериментальной интеграции Ula в 3.0.16 нет.
Проверка Oracle и подключение к стороннему биллингу не выполняются.
Стабильная 3.0.15 не изменяется.

«Информация по камере»:
- Вкладка поиска переименована из «Камеры · проверка и превью» в «Информация по камере»; большой встроенный блок превью убран.
- Карточка камеры читается напрямую из B2O без требования архивной подписи, DVR-сервера или HLS; отображаются доступные сведения (ID, название, статус, сервер, IP, серийный номер, глубина архива).
- При длинном числовом идентификаторе и точном HTTP 404 можно выполнить безопасную проверку совпадения по серийному номеру. Поиск не принимает произвольные URL.
- Если токен отсутствует, используется текущая учётная запись «Админка»; статус ошибки отображает безопасную категорию вместо произвольного ответа API.

Диагностика кратковременных Windows-окон:
- Продлён безопасный журнал дочерних процессов на всё время работы приложения и добавлены метки первого открытия каждой вкладки для корреляции всплывающего CMD.
- Источник CMD пока требует проверки на рабочем Windows: в коде уже есть подавление консольных окон Python subprocess, но локальный флэш может быть вызван другим механизмом.
