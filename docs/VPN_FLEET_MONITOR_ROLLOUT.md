# LinkVideo.Helper: постоянный мониторинг VPN и подготовка флота

## Что уже работает независимо от открытого Helper

RouterOS Scheduler запускает LV-Activity (10 мин), LV-AutoRestore (1 мин) и LV-Aging (1 раз/сутки) на самом MikroTik. После включения они работают и при закрытом Helper, и при выключенном ПК.

Это **не то же самое**, что отдельная фоновая синхронизация Google Sheets. В десктопе Google Sheets сейчас сознательно используется как ручной аварийный резерв; старый автоматический экспорт клиентов хранил PPP-пароли и полные снимки конфигурации. Не включать его массово без отдельного согласованного решения о хранении секретов.

## Новый безопасный мониторинг (пилот, не включён автоматически)

Добавлен `scripts/vpn_fleet_health_agent.py`. Он читает **только** агрегированные RouterOS-метрики и состояние LV-автоматики. Каждые 300 секунд записывает в отдельную вкладку `LV Мониторинг`: сервер, UTC проверки, состояние RouterOS API, L2TP онлайн/всего, NAT порты, CPU, RAM, статус/версию LV, счётчики запусков. PPP логины, пароли, IP клиентов и восстановления в этом отчёте **не экспортируются**.

Фоновая задача Windows по умолчанию проверяет **только `vpn01.linkvideo.ru`** в режиме canary. Остальные серверы добавляются явным параметром `-Servers` после проверки доступа. Список из 12 серверов остаётся доступным для отдельного конфигурирования Python-агента.

В Windows: `scripts/install_windows_vpn_fleet_monitor.ps1` создаёт задачу Task Scheduler `LinkVideo.VPN.FleetMonitor`, которая стартует при загрузке ПК от SYSTEM, не требует запуска GUI и перезапускается после сбоя. Исходники и Python venv должны находиться в *постоянной*, доступной для SYSTEM папке. Стандартный установщик Helper эту задачу **не регистрирует** для всех сотрудников.

### Настройка пилота на выделенном включённом ПК

1. Подготовить постоянную папку с этим репозиторием и Python venv с установленными зависимостями приложения. Использовать учётку RouterOS **только для чтения**, отдельно от рабочего администратора.
2. Подготовить Google service-account JSON с доступом только к нужной Google-таблице. Не присылать приватный ключ в чат и не коммитить его. На целевом ПК запустить PowerShell **от администратора**:
   `.\scripts\install_windows_vpn_fleet_monitor.ps1 -RepositoryRoot "C:\LinkVideo\source" -PythonExe "C:\LinkVideo\source\.venv\Scripts\python.exe" -ServiceAccountJson "C:\Secure\service-account.json"`
3. Скрипт спросит RouterOS username/password, защитит конфигурацию и JSON Google от чтения обычными пользователями через NTFS ACL (только SYSTEM и Administrators), проверит RouterOS в режиме `--dry-run`, затем зарегистрирует и запустит фоновую задачу.
4. Проверить `Get-ScheduledTask -TaskName LinkVideo.VPN.FleetMonitor | Get-ScheduledTaskInfo` и журнал `C:\ProgramData\LinkVideo.Helper\VPNFleet\vpn-health.log`. Таблица обновится в `LV Мониторинг` при доступном Google API.

Ограничение: при выключенном ПК задача не работает. Для 24/7 правильнее установить существующий `server/linkvideo_vpnsync` как Linux systemd-службу на постоянно работающем сервере.

### Раскатка LV-автоматики на все RouterOS: отдельный этап

Не путать с мониторингом. Установка/включение LV Scheduler может изменять состояние PPP secret. Безопасный порядок: бэкап каждого сервера → проверить устройство и RouterOS device-mode → один canary (vpn01) → проверить LV-Activity/AutoRestore 24 часа, проверить `LV-Aging` и режим карантина → только после этого добавлять следующие серверы небольшими партиями с проверкой состояния и отката.

Helper уже содержит в разделе VPN-серверов функции «Установить LV на все» и «Запустить LV на всех». Они **не запускались** этим изменением. Рекомендуется сначала запускать только на одном сервере и сохранить `LV-Aging` выключенным до проверки истории активности.
