# Ula (Россия) — интеграция в LinkVideo.Helper 3.0.16

## Цель
Найти клиента в российском сегменте и показать его действующие услуги,
название каждого тарифа и сумму из Ula. Изменение тарифов не входит в задачу.

## Подтверждено захватом от 29.10.2026
Поиск клиента: `devdb.get_clients_by_filter_ula(:search_text, :type)`.

Получение услуг:
```sql
begin
  :result := crm.get_client_services_list(
    p_id_client       => :id_client,
    p_is_non_active   => :is_non_active,
    p_is_group_client => :is_group_client
  );
end;
```

В результирующем наборе подтверждены имена `ID_CONTRACT_SERVICE`,
`SERVICE_NAME`, `TARIFF_NAME`, `COSTS`, `DISCOUNT`,
`STATUS`, `IS_ACTIVE_SERVICE`, `DOG_NUM`, `COST_CONNECT`.
`COST_CONNECT` — отдельная стоимость подключения; не подменяет `COSTS`.

**Не считать `COSTS` месячной платой до сверки.**
Не использовать `crm.vw_sell_more` для действующих услуг:
по одному названию нельзя исключить, что это дополнительные предложения.

## Реализованная основа
`linkvideo_vpn_helper/services/ula_oracle_gateway.py`:
типизированные строки, защита от некорректного курсора и больших выборок,
bind-переменные, никаких записывающих SQL-команд, паролей или адресов серверов.
Соединение и тип Oracle REF CURSOR передаются вызывающим кодом.
Без реального авторизованного подключения функция пока не проверялась.

## Важное: авторизация Ula через Oracle RADIUS
В установленном дистрибутиве Ula обнаружен `sqlnet.ora` с настройкой
`SQLNET.AUTHENTICATION_SERVICES=(RADIUS)`. Это не обычный database-password вход.
В python-oracledb Thin RADIUS не поддерживается; нужен Oracle Thick с OCI.

Новая RC при импорте `Ula.ini` определяет `sqlnet.ora` рядом с ним,
не сохраняет пароль и при наличии RADIUS автоматически ищет уже
установленную совместимую 64-битную OCI-библиотеку в каталоге Ula,
в переменных окружения и стандартных каталогах Oracle. Файлы `oci.dll`
проверяются по PE-заголовку без загрузки; 32-битная Ula OCI отвергается.
Если совместимая библиотека не найдена, вместо тихого перехода на Thin
выдаётся понятная ошибка и предлагается ручной выбор в расширенных
настройках. `sqlnet.ora` передаётся через `config_dir`.
Ключи и пароли не копируются в публичный GitHub или логи.

**Остаётся неподтверждённым:** совпадает ли имя пользователя Oracle из
`Ula.ini` и пароль для входа в Ula с парой, разрешённой сервером
Oracle/RADIUS. Наличие RADIUS и успешная загрузка Oracle Thick **не
гарантируют** отсутствие ORA-01017. Нельзя выдавать эти события за
успешную аутентификацию сотрудника Ula. Для проверки реального способа
входа нужны подтверждённые параметры штатной авторизации. Права SYS/DBA
не требуются. OCI x86 нельзя напрямую загрузить в Helper x64.

Официальный клиент: https://www.oracle.com/database/technologies/instant-client/winx64-64-downloads.html

Никакого подбора паролей, извлечения чужих учётных данных или обхода
сетевой аутентификации приложение не выполняет.
