# Google Sheets: зеркало VPN RouterOS

Google Sheets используется LinkVideo.Helper как вторичное аварийное зеркало, архив удалённых VPN-учёток и журнал изменений. **RouterOS остаётся источником текущего состояния**: данные из Sheets не должны самопроизвольно менять MikroTik. Обратная запись в RouterOS выполняется только при явном восстановлении архивной учётки оператором.

## Рабочие листы

- `LV vpn01` … `LV vpn10`
- `LV rb-vpn01`
- `LV kz-vpn01`
- `LV История`
- `LV Удалённые`

`LV Сводка` больше не используется и удалена из рабочей таблицы.

Одна VPN-учётка на серверном листе = одна строка. Ключ: `server + login`.

### Колонки серверного листа

1. Логин
2. Пароль
3. Service
4. Profile
5. Local Address
6. Remote Address
7. Комментарий RouterOS
8. NAT / Порты
9. Lifecycle
10. PPP disabled
11. Последняя активность
12. Дней без связи
13. Первое обнаружение
14. Последнее изменение
15. Удалена
16. Удалена в
17. Последняя сверка RouterOS
18. Источник
19. RouterOS snapshot
20. Причина

`Service`, `Profile`, служебные колонки и полный snapshot сохраняются для восстановления/диагностики, но часть из них скрывается в обычном операторском представлении.

`NAT / Порты` показывает только внешние порты, например `10562; 10563; 10564`. Полная схема NAT, включая protocol, `dst-port`, `to-addresses`, `to-port` и disabled, остаётся в `RouterOS snapshot`. Поэтому сокращённое отображение не теряет данные восстановления.

Если RouterOS возвращает `jan/01/1970 00:00:00` для учётки, которая ни разу не подключалась, оператору показывается `Никогда`.

`Пароль` и `RouterOS snapshot` являются recovery-данными; доступ к таблице должен быть ограничен.

### `LV Удалённые`

Когда VPN-учётка исчезла после успешного полного чтения RouterOS, она удаляется из рабочего `LV vpnXX` и переносится в единый архив `LV Удалённые`.

В архиве сохраняются:

- VPN-сервер и логин;
- пароль;
- Service/Profile;
- Local/Remote Address;
- NAT-порты;
- Lifecycle и последняя активность;
- время/причина удаления и инициатор;
- полный RouterOS snapshot.

Поиск Helper просматривает этот архив. Восстановление выполняется только явно оператором. Свободные старые внешние порты сохраняются; если старый внешний порт уже занят другим клиентом, Helper выбирает новый свободный внешний порт и сохраняет исходный внутренний `to-port`. Чужое NAT-правило никогда не перезаписывается.

### `LV История`

История предназначена для оператора, а не для отображения сырых JSON-дампов. Новые события получают понятные действия, например:

- `Новая VPN-учётка`;
- `Изменены NAT-порты`;
- `Изменён VPN IP`;
- `Изменён пароль`;
- `Переведена в спящие: 30+ дней без активности`;
- `Отключена автоматически: 90+ дней без активности`;
- `Удалена автоматически`;
- `Восстановлена VPN-учётка`.

Для NAT-изменения указываются добавленные/удалённые внешние порты. Автоматические действия подписываются как `Автоматически`; для действий через Helper сохраняется инициатор/логин сотрудника.

Пароль и полный snapshot не выводятся открытым текстом в человекочитаемых `Было/Стало`. ID операции/Sync ID остаётся техническим механизмом защиты истории от дублей при неопределённом результате Google append.

## Правила сверки

1. RouterOS успешно прочитан, учётка есть на RouterOS, строки нет в Sheets → создать строку.
2. Учётка есть в обоих местах → обновлять только реальные изменения.
3. Строка есть в Sheets, но учётки нет после **успешного полного** чтения `/ppp/secret` → перенести её из рабочего листа в `LV Удалённые` и записать событие.
4. RouterOS недоступен, snapshot неполный или чтение завершилось ошибкой → ничего не считать удалённым.
5. Уже сохранённый пароль нельзя затирать пустым значением, если текущие права RouterOS API скрыли sensitive-поле.
6. Переход со старого `tcp 10001→10001` на компактное `10001` нормализуется до сравнения и не создаёт ложные массовые события изменения NAT.

## Retention 30/90/365

Для учёток с подтверждённой активностью:

- 30+ дней без связи → `Спящая 30+`;
- 90+ дней → `Карантин 90+` и PPP disabled;
- 365+ дней → автоматическое удаление PPP secret, относящихся NAT-правил и неиспользуемого индивидуального Profile.

Для учёток, которые ни разу не подключались, используется отдельное правило: удаление через 30 дней от известной даты создания/начала отслеживания.

`LV-Aging` остаётся автономным RouterOS-механизмом. Дополнительно Helper после безопасного сохранения текущего состояния в Google Sheets проверяет просроченные записи. Если `LV-Aging` включён, но scheduler пропустил удаление, Helper применяет policy и повторно синхронизирует сервер, чтобы удалённая запись сразу попала в `LV Удалённые`. Если оператор намеренно выключил `LV-Aging`, эта страховка ничего не удаляет.

## Устойчивость синхронизации

Синхронизация защищена от временных проблем Google API:

- connect timeout — 6 секунд;
- read timeout — не менее 30 секунд;
- до 3 попыток для безопасно повторяемых запросов;
- backoff/jitter и учёт `Retry-After`;
- максимум 2 одновременных Google-запроса из Helper;
- одна подготовка схемы перед полной синхронизацией;
- запись серверных строк блоками по 350;
- после двух независимых полностью повторённых временных Google-сбоев полная синхронизация включает circuit breaker и перестаёт бессмысленно нагружать API;
- небезопасный повтор append истории не выполняется вслепую: сначала проверяется ID операции.

Серверные листы автоматически приводятся к 20 колонкам через идемпотентное изменение `columnCount`.

## Источники изменений

- `Helper · ...` — успешная операция выполнена через LinkVideo.Helper;
- `Ручная синхронизация Helper` — оператор нажал `Синхронизировать`;
- `Автосверка RouterOS` — периодическая сверка открытого Helper;
- `LinkVideo.VPNSync` — независимый центральный агент.

Изменения через WinBox обнаруживаются следующей успешной полной сверкой.

## Service account

По умолчанию ключ ищется в:

`%PROGRAMDATA%\LinkVideo\Helper\google_sheets_service_account.json`

Также поддерживаются:

- `LINKVIDEO_SHEETS_SERVICE_ACCOUNT_FILE`;
- `LINKVIDEO_SHEETS_SERVICE_ACCOUNT_JSON`;
- QSettings `sheets/service_account_file`.

Приватный ключ не должен попадать в GitHub или EXE.
