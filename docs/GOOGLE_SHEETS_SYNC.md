# Google Sheets: зеркало VPN RouterOS

Google Sheets используется LinkVideo.Helper как вторичное аварийное зеркало и журнал изменений. **RouterOS остаётся источником текущего состояния**: данные из Sheets сами по себе никогда не должны менять MikroTik.

## Рабочие листы

- `LV vpn01` … `LV vpn10`
- `LV rb-vpn01`
- `LV kz-vpn01`
- `LV Сводка`
- `LV История`

Одна VPN-учётка на серверном листе = одна строка. Ключ: `server + login`.

### Колонки серверного листа

1. Логин
2. Пароль
3. Service
4. Profile
5. Local Address
6. Remote Address
7. Комментарий RouterOS
8. NAT / Порты
9. Lifecycle
10. PPP disabled

12. Дней без связи
13. Первое обнаружение
14. Последнее изменение
15. Удалена
16. Удалена в

18. Источник
19. RouterOS snapshot
20. Причина

`Пароль` и `RouterOS snapshot` нужны для аварийного восстановления; доступ к таблице должен быть ограничен.

### `LV История`

Неизменяемый журнал синхронизации:

- время;
- VPN-сервер;
- логин;
- событие;
- изменённые поля;
- было;
- стало;
- источник;
- инициатор;
- Sync ID.

Пароли и полный snapshot не дублируются открытым текстом в `Было/Стало`. `Sync ID` используется для защиты от дублирования события, если Google принял append, но клиент получил timeout и не знает результат операции.

## Правила сверки

1. RouterOS успешно прочитан, учётка есть на RouterOS, строки нет в Sheets → создать строку.
2. Учётка есть в обоих местах → обновлять только реальные изменения.
3. Строка есть в Sheets, но учётки нет после **успешного полного** чтения `/ppp/secret` → пометить удалённой и записать событие.
4. Ранее удалённая учётка снова появилась → восстановить существующую строку без дубля.
5. RouterOS недоступен, snapshot неполный или чтение завершилось ошибкой → ничего не помечать удалённым.

## Устойчивость синхронизации

Начиная с 3.0.10/3.0.11 синхронизация защищена от временных проблем Google API:

- connect timeout — 6 секунд;
- read timeout — не менее 30 секунд;
- до 3 попыток для безопасно повторяемых запросов;
- backoff/jitter и учёт `Retry-After`;
- максимум 2 одновременных Google-запроса из Helper;
- одна подготовка схемы перед полной синхронизацией;
- запись серверных строк блоками по 350;
- `LV Сводка` вторична и её ошибка не должна ломать успешную сверку сервера;
- после двух независимых полностью повторённых временных Google-сбоев полная синхронизация включает circuit breaker и перестаёт бессмысленно нагружать API;
- небезопасный повтор `append` истории не выполняется вслепую: сначала проверяется `Sync ID`.

Серверные листы автоматически приводятся к 20 колонкам через идемпотентное изменение `columnCount`.

## Источники изменений

- `Helper · ...` — успешная операция выполнена через LinkVideo.Helper;
- `Ручная синхронизация Helper` — оператор нажал `Синхронизировать`;
- `Автосверка RouterOS` — периодическая сверка открытого Helper;
- `LinkVideo.VPNSync` — независимый центральный агент.

Изменения через WinBox обнаруживаются следующей успешной полной сверкой.

## Service account

По умолчанию ключ ищется в:

`%PROGRAMDATA%\LinkVideo\Helper\google_sheets_service_account.json`

Также поддерживаются:

- `LINKVIDEO_SHEETS_SERVICE_ACCOUNT_FILE`;
- `LINKVIDEO_SHEETS_SERVICE_ACCOUNT_JSON`;
- QSettings `sheets/service_account_file`.

Приватный ключ не должен попадать в GitHub или EXE.
