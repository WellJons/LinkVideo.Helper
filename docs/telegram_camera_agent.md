# Telegram-бот LinkVideo: доступ по приглашению (RC)

Бот работает **отдельным фоновым процессом** от LinkVideo.Helper. Когда GUI
закрыт, процесс бота не обязан завершаться. На компьютере, где по очереди
работают разные сотрудники, для постоянной работы требуется установка бота
как службы под отдельной системной учётной записью. **Установщик службы и
независимая авторизация B2O ещё не реализованы.**

## Доступ без ручного добавления сотрудников

Telegram не поддерживает скрытого по username бота: его имя видно в поиске,
но это **не означает разрешение выполнять команды**.

1. Администратор генерирует секретную ссылку вида
   `https://t.me/LinkVideoHelperBot?start=<random>`.
2. Сотрудник нажимает ссылку и Start — бот автоматически допускает его
   Telegram-аккаунт, не требуя вручную вводить Telegram ID.
3. Разрешение хранится в SQLite на машине службы и переживает перезапуск.
   Обычная ссылка без `?start=` не даёт доступ.
4. Ссылка обычно **одноразовая**, действует 24 часа. После активации
   сотрудник пользуется ботом без повторной авторизации.
5. Если требуется отозвать доступ, администратор удаляет его по Telegram ID.
   Для этого достаточно получить ID из служебного журнала или БД.

Небольшие изменения прав доступа — не регистрация в системе и не отдельная
привязка аккаунтов B2O. Они нужны, чтобы случайные люди, которые нашли
username бота, не видели камеры и не могли создавать VPN.

## Создание ссылки-приглашения

В установленном окружении исходников проекта:

```powershell
python -m linkvideo_vpn_helper.services.telegram_camera_agent invite --username LinkVideoHelperBot
```

Опционально: `--hours 48 --uses 5` для ссылки сроком 48 часов
с пятью активациями. Это удобнее, но её можно пересылать; для доступа к
видеокамерам лучше выдавать одноразовые приглашения.

Снять доступ:
```powershell
python -m linkvideo_vpn_helper.services.telegram_camera_agent revoke --id 123456789
```

База: `%ProgramData%\LinkVideo\Bot\invites.sqlite3` на Windows, либо
путь из `LINKVIDEO_TELEGRAM_STATE_DB`. **Каталог должен иметь ACL,
ограничивающий чтение/изменение только служебной учётной записью и
администраторами.** Процесс генерации ссылок и сама служба должны
использовать одну и ту же БД.

## Функции текущего прототипа

- `/client ЛОГИН` — проверенный поиск камер России по точному логину
  владельца, до 20 камер и 4 превью.
- `/camera ID` — основная RTSP-диагностика, текущий битрейт и FPS, если
  удалось получить медиаданные.
- Просмотр в группах отключён; только личные чаты.
- Все RTSP-пароли, бот-токен и токен B2O остаются на машине бота.
- Правила транскода H.264/H.265 + AAC и side-task берутся из общего
  `camera_stream_format.py`.

**Создание VPN через Telegram ещё не реализовано**. Перед включением этой
операции потребуется отдельно защитить её подтверждением,
идемпотентностью и журналом. Код просмотра камер нельзя автоматически
наделять правом записи на MikroTik.

## Запуск процесса (только для разработки)

```powershell
$env:LINKVIDEO_TELEGRAM_BOT_TOKEN = 'СЕКРЕТ_BOTFATHER'
python -m linkvideo_vpn_helper.services.telegram_camera_agent
```

Бот начнёт опрашивать Telegram независимо от GUI, но **текущий код всё ещё
читает B2O-сессию из QSettings системной учётной записи, запустившей процесс**.
При входе разных пользователей Windows эти настройки НЕ передаются службе.
Для полностью автономной службы нужно решить, какие разрешённые данные
B2O она будет использовать, и хранить их отдельно и защищённо. Нельзя
брать произвольную последнюю пользовательскую сессию или вшивать общий
пароль в EXE.

Администратору не нужно отправлять разработчику BotFather токен, приватный
SSH-ключ или пароль B2O.

### Реальный статус реализации

Генерация приглашений, автоматическая регистрация по ссылке, хранение
и отзыв доступа готовы в исходном коде RC. Служба Windows,
устойчивая авторизация B2O и Telegram VPN-create — отдельные незавершённые
части. До их реализации нельзя считать бот готовым для круглосуточной
эксплуатации.
