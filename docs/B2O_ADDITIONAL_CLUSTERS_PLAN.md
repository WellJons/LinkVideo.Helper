# Дополнительные B2O-кластеры в LinkVideo.Helper

Статус: технический план. Управление дополнительными DVR-серверами **существующих** трёх операторов реализовано отдельно в «Настройки → Архив». Создание новых B2O-операторов/кластеров пока НЕ включено в активный поиск — для него нужен подтверждённый сетевой контракт.

## Почему одного Request URL недостаточно

Текущий B2O-модуль использует несколько независимых API:

- \`GET /ords/mobile/vc2/operators/{operator}/cameras/{camera}\` — карточка камеры, \`server_name\`, \`main_stream_name\` или \`nimble_id\`, \`signature\` или \`wmsAuthSign\`, время камеры.
- \`GET /ords/mobile/vc2/operators/{operator}/servers\` и fallback \`/dvr-servers\`, \`/media-servers\` — реальные host'ы DVR/vcore, не список придуманной нумерации.
- \`GET /ords/mobile/vc2/admin/reserve-transfers\` — история переводов между DVR.
- HLS player / Nimble URLs по временным плейлистам и разным host'ам — последний шаг поиска и скачивания MP4.

Уже реализованы три фиксированных оператора: Россия \`241/linkvideo_\`, Казахстан \`1721/linkvideokz_\`, Беларусь \`1741/linkvideoby_\`. Возможность добавить **сервер** к этим профилям хранится в \`archive/custom_servers/{operator_id}\` и участвует в глубоком fallback-поиске.

Новый кластер может означать две разные задачи:

1. Тот же оператор B2O, но новый DVR/vcore: **достаточно доменного имени сервера**, не нужен новый Request URL, решение уже доступно в настройках.
2. Другой оператор B2O, пусть даже той же страны и под тем же входом в «Админку»: понадобятся **ID оператора**, префикс ID камер, схема API, права сессии, серверная инвентаризация и player/HLS. Нельзя автоматически вывести всё из одной ссылки страницы.

## Дизайн мастера добавления нового оператора (после проверки API)

1. «Название» (локальная подпись), «Страна/регион» (не ключ), **проверенный ID оператора** и префикс ID камеры. Поиск оператора по примеру очищенного Request URL; без записи Cookie/Token или query-параметров.
2. Проверка авторизации уже действующей сессией «Админки» и чтение тестовой камеры. Обязательны ID, server_name, stream name и signature; при неполном ответе **не сохранять активный профиль**.
3. Проверка инвентаризации \`/servers\` (или известных fallback) и HLS player playlist на заданном периоде; классифицировать сетевые ошибки отдельно от «нет записи».
4. Сохранить только безопасную конфигурацию (ID/префикс/название/подтверждённые host'ы). Привязка к существующей защищённой авторизации, без ручного сохранения токена и подписанных ссылок.
5. Добавить динамический выбор **кластера/оператора** в «Скачать архив» и «Диагностика архива». Текущий переключатель «Страна» будет недостаточен, если одной стране принадлежат несколько кластеров. Не подменять выбранный кластер по умолчанию.
6. Кнопки «Проверить», «Отключить», «Удалить»; предупреждение о том, что удаление не удаляет реальные записи. Никаких изменений на B2O-серверах из интерфейса.

## Что нужно увидеть в DevTools без секретов

- **Network → Fetch/XHR** и адрес одного чтения списка камер, чтобы найти \`/operators/{id}/...\`.
- Одну обезличенную **структуру JSON** карточки камеры (только имена полей, не значения подписей/логинов).
- Endpoint списка серверов и признак происхождения HLS-ссылки. Полные подписанные URL, Authorization/Token/Cookie, пароль и клиентские данные **не пересылать**.
- Уточнить, новый ли это operator ID, или просто новый DVR существующего ID.

Перед выпуском нужны офлайн-тесты новых профилей, проверка авторизации, поиск в двух кластерах одной страны, переносов, HLS, сценария с истёкшей подписью и Windows RC.
