LinkVideo.Helper 3.0.11

Архив
- Возвращён выбор метода скачивания: FFmpeg, Curl и «Без звука».
- Сохранён автоматический поиск реального DVR/vcore для всех методов.
- FFmpeg больше не встраивается в Setup. При первом использовании он скачивается в %LOCALAPPDATA%\LinkVideo.Helper\tools, показывает реальный прогресс, сверяется с официальным SHA-256 и затем переиспользуется из кэша.
- Curl снова использует прямой Nimble export_mp4.
- Режим «Без звука» всегда исключает аудиодорожку через -an.
- Добавлена гарантированная остановка дочерних curl/ffmpeg-процессов при отмене, timeout и ошибках, даже если stdout FFmpeg завис.
- Итоговый MP4 теперь сначала пишется во временный файл в выбранной папке и появляется под конечным именем только после успешного завершения; отмена/ошибка не оставляет повреждённый архив.
- Безопасные архивные методы теперь подключены непосредственно в ArchiveService; удалены скрытые startup monkey-patch для загрузчика и глобальная подмена subprocess.Popen. Сетевые FFmpeg timeout/nostdin задаются прямо в команде.
- Curl-ответы и итоговый файл теперь проверяются как настоящий MP4 до атомарной замены; HTTP 200 с HTML/JSON больше не сохраняется как готовый архив.

VPN / Google Sheets
- Синхронизация Google Sheets получила повтор безопасных запросов, увеличенный read timeout, ограничение параллелизма и connection pooling.
- Полная сверка использует одну подготовку схемы, запись блоками и circuit breaker вместо одновременного штурма Google API.
- Неопределённый результат append истории защищён Sync ID и не создаёт дубликаты.
- Серверные листы автоматически приводятся к актуальной 20-колоночной схеме с колонкой «Причина».
- LV2 lifecycle/retention остаётся авторитетным при синхронизации.
- Откат создания VPN-клиента/портов больше не прекращается после первой ошибки удаления: Helper пытается очистить все созданные объекты и явно сообщает, если автоматическая очистка выполнена не полностью.
- Исправлена синхронизация состояния LV-Aging в таблице VPN-серверов: после подтверждённого изменения RouterOS статус меняется сразу и не дублирует «карантин включён».

Обновление и установщик
- Единственный официальный Setup — LinkVideo.Helper_Setup.exe из installer_next; старый Inno release-path полностью удалён.
- Полный upgrade сначала распаковывает и проверяет новый runtime в отдельной staging-папке, затем атомарно заменяет старую версию. При сбое старый runtime восстанавливается; настройки и LocalAppData-кэш не трогаются.
- Перед полным upgrade останавливаются task/worker предыдущего фонового updater, чтобы Setup и патч не могли одновременно менять Program Files.
- Исправлена основная проверка Windows ProductVersion в update_service; дублирующий compatibility monkey-patch удалён.
- В полном и тихом patcher проверка ProductVersion выполняется до записи DisplayVersion в реестр; ошибка отката больше не скрывается, а флаг --silent сохраняется при UAC-перезапуске.
- Перед запуском обновления сохраняются проверки SHA-256 и ProductVersion.
- Манифест с новой версией без SHA-256, невалидная версия, HTTP-ссылка или слишком большой файл теперь блокируются.
- Setup не содержит ffmpeg.exe.

Проверка релиза
- Корень репозитория очищен от старых BUILD_RELEASE_*.bat, исторических README/RELEASE-файлов и устаревших сборочных путей; история остаётся в Git.
- Добавлен единый scripts/verify_release.ps1, одинаковый для локальной Windows и CI.
- Release gate включает: compile Python, полный source-аудит, все core regressions, Ruff, go vet, clean PyInstaller build, сборку Setup/Uninstall, compile differential patch pipeline, проверку ProductVersion и SHA-256.
- Проверенные best-effort `except ...: pass` зафиксированы структурным allowlist; новое или изменённое проглатывание исключения блокирует релиз.
- Точный произведённый Setup проходит side-effect-free --self-test: проверяются встроенный payload, staging/атомарная замена, восстановление при прерванном upgrade, обязательные EXE и отсутствие встроенного FFmpeg.
- Результат проверки фиксируется в verification.json.
- Публичный публикатор сверяет Setup с verification.json и commit тега, блокирует откат канала на старую версию и запрещает замену уже опубликованной версии другими байтами.
- Повторный final workflow не может заменить assets уже опубликованного приватного Release; обновлять разрешено только draft.
- Production manifest 3.0.11 принудительно публикуется без дифференциальных патчей: компьютеры с 3.0.10 получают полный атомарный Setup. Патчи остаются отключёнными до отдельной проверки восстановления после сбоя питания.
- Actions artifacts больше не являются частью release-chain. Для версии используется один приватный draft RC, который заменяется следующей успешно проверенной сборкой вместо накопления старых артефактов.
- Тяжёлый Windows CI запускается для PR в main, явной rc/** ветки, final v* tag или вручную, а не на каждом development-коммите; приватный RC создаётся только из rc/**.

Перед публичной публикацией обязательна ручная проверка на Windows сначала RC, а затем именного точного Setup из final draft: обновление с 3.0.10, запуск программы, все три метода архива, первая/повторная загрузка FFmpeg, Google Sheets и основные операции RouterOS/VPN. Только после этого final Release публикуется и попадает в GitHub update-channel.
